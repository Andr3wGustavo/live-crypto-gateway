# Internacionalização do frontend

## Implementação

- `src/i18n/locale.ts`: idiomas, negociação, caminhos e formatação decimal exata.
- `src/i18n/messages.ts`: catálogos completos da interface em `en`, `pt-BR` e `es`, com tipos compartilhados.
- `src/i18n/Provider.tsx`: acesso aos textos/formatadores no cliente e seletor acessível.
- `src/proxy.ts`: redireciona caminhos sem locale; não intercepta API ou assets.
- `src/app/[locale]`: rotas localizadas com `lang`, metadata e geração das landings por idioma.
- `sitemap.ts`: somente URLs públicas da landing; nunca incluir tokens do OBS.

Não é necessária uma API de tradução para renderizar as páginas. Somente o catálogo selecionado é passado ao provider do cliente.

## Escolha de idioma

1. Prefixo explícito na URL (`/en`, `/pt-BR`, `/es`).
2. Cookie `livecrypto_locale` salvo pelo seletor por um ano.
3. Preferências `Accept-Language` respeitando pesos `q` e variantes regionais.
4. País recebido em `X-Country-Code`, exclusivamente se `TRUST_GEO_COUNTRY_HEADER=true` e proxy confiável sobrescrever o cabeçalho.
5. Inglês.

Redirecionamentos negociados têm `Cache-Control: private, no-store`; evitar que CDN compartilhe entre visitantes uma decisão de idioma. Nunca alterar a rede de pagamento pelo país ou idioma.

## Navegação e dados

- Use `localePath(locale, '/login')` no servidor e `path('/login')` do hook no cliente.
- A API permanece em `/api`, sem prefixo de idioma.
- A URL pública compartilhada de doação não precisa fixar idioma; o destinatário escolhe. A URL OBS copiada pelo criador fixa o locale e não contém seletor.
- `number()` formata números de exibição. `decimal()` preserva strings cripto exatas sem converter para ponto flutuante.
- `date()` usa UTC explicitamente; não adivinhar fuso a partir do idioma.
- Mensagens personalizadas, nomes de rede/marca, ticker e protocolos de assinatura não devem ser traduzidos automaticamente.
- Idioma do Web Speech acompanha o overlay; disponibilidade da voz depende do sistema/OBS. O texto é enviado no idioma selecionado quando o serviço neural é habilitado.

## Adicionar idioma

1. Incluir o locale BCP 47 e nome nativo em `locale.ts`.
2. Criar catálogo do tipo `Messages` e adicionar em `dictionaries`.
3. Atualizar negociação de variantes e, se apropriado, fallback por país.
4. Incluir metadata/hreflang da landing e testar sitemap.
5. Para idiomas RTL, implementar direção/fontes e testar layout; os três idiomas atuais usam LTR.
6. Executar `npm run test:i18n`, TypeScript, lint, build e testes HTTP/visuais.

Não usar tradutor DOM nem substituir texto depois da hidratação. Não anunciar um idioma antes de traduzir erros, acessibilidade e textos financeiros, além de revisar o layout.

## Verificação

`npm run test:i18n` verifica negociação, caminhos, cobertura dos catálogos e precisão decimal. Testes HTTP opcionais exigem o app iniciado pelo `.bat` e `I18N_TEST_URL=http://localhost:3000`.

Esses testes não substituem uma revisão humana das traduções nem testes de carteira real, acessibilidade e screenshots em celular/desktop.
